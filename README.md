# RecoveryApp

Бесплатное некоммерческое приложение для macOS: восстановление удалённых файлов
и исправление повреждённого видео. Нативный русский интерфейс на SwiftUI и CLI
используют один backend — **RecoveryCore на Swift**.

**Текущая версия: 0.8.1 (13), лабораторная.** Требуется Apple Silicon и macOS 14+.
Для запуска готового приложения Swift и Xcode не нужны.

## Возможности

- Быстрый поиск удалённых записей FAT32/exFAT через `mmls`, `fls`, `icat`:
  попытка сохранить имена, выбор файлов, фильтры типа, имени и размера.
- Глубокий поиск JPEG, PNG и MOV/MP4 через PhotoRec: без исходных имён и папок.
- Исправление видео через `untrunc` по исправному примеру с того же устройства.
- Карточки результата, открытие папки/файла в Finder, подробный локальный лог.
- CLI: поиск и восстановление из образов и с внешних дисков, исправление видео,
  JSON-отчёты и JSONL-события для автоматизации.

Источник открывается только для чтения. Результат сохраняется на другой
физический диск; перед операцией накопитель обнаруживается и сверяется заново.
Системное разрешение выдаёт macOS — приложение не принимает и не хранит пароль.
Отмена останавливает группу процессов; найденные PhotoRec файлы сохраняются.

Восстановление не гарантируется: перезапись и фрагментация могут сделать результат
неполным. Совпадение размеров не доказывает целостность содержимого. Точный ETA
не обещается. Сети и телеметрии сейчас нет; сеть, телеметрия и автообновления
оставлены на отдельный будущий этап с явным согласием пользователя.

## Быстрый старт разработчика

Нужны Swift 6 / Command Line Tools либо Xcode. Запускайте команды из корня Git:

```sh
git rev-parse --show-toplevel
./Scripts/test.sh
swift build -c release --product recoveryapp-cli
```

Сборка `.app` и упаковочные сценарии могут заменять ранее созданные артефакты
в своей папке назначения. Используйте новую папку, как описано в
[руководстве разработчика](docs/DEVELOPMENT.md). Пути сторонних инструментов
для standalone CLI нужно настроить отдельно.

## Проверено и пока не проверено

Синтетические FAT32/exFAT, PhotoRec, untrunc, отмена процессов, общий Core/CLI,
GUI-сценарии и ad-hoc-подпись проверялись в отдельных задачах. Доменный harness
при приёмке TASK-016: **308 проверок**. Реальные тесты были ограниченными:
короткое чтение Flashka и отдельный поиск/извлечение на 2-ГБ FAT32-носителе.
Это не доказывает восстановление любых данных и любых форматов.

Последняя контрольная сборка инструментов — TASK-016. Ранние DMG/ZIP — снимки
своих задач, а не автоматически обновлённые релизы. Чистая установка на другом
Mac, расширенные реальные тесты и вопросы распространения остаются открытыми.
Точные команды, результаты и границы — в [отчётах](reports/) и [очереди](TASKS.md).

## Лицензии и распространение

Код RecoveryApp — [GPL v2](LICENSE). Встроены PhotoRec 7.2, libjpeg-turbo 3.2.0,
Sleuth Kit 4.15.0 и снимок untrunc со статическим FFmpeg 8.1. Они запускаются
отдельными CLI-процессами; Sleuth Kit не линкуется в RecoveryCore.

В `.app` включаются уведомления, исходные архивы, патчи и evidence контрольных
сборок. [Аудит комплектности](docs/DISTRIBUTION_CHECKLIST.md) и
[provenance инструментов](docs/TOOLCHAIN_PROVENANCE.md) — инженерные проверки,
не юридическое заключение. Повторная проверка 2026-10-07 подтвердила
соответствие архива untrunc коммиту; добавлены датированные уведомления патчей
и THIRD-PARTY-NOTICES.txt. По текущим отдельным CLI-интерфейсам общего запрета
на совместную поставку не установлено. Исходники прикладываются к тому же
релизу, условия каждого компонента сохраняются. Публичная публикация пакета —
отдельное решение владельца; чистая установка на другом Mac ещё не проверена.

Нет Developer ID, hardened runtime и нотариализации. Приложение нельзя считать
готовым массовым релизом. Для тестового первого запуска используется официальное
действие macOS «Всё равно открыть», без отключения Gatekeeper; подробнее —
[руководство пользователя](docs/USER_GUIDE.md).
