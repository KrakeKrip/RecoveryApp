# Аудит лицензий Sleuth Kit 4.15.0

Дата: 2026-09-13

## Итог

`fls`, `icat` и `mmls` нельзя линковать с RecoveryApp в единый GPL-бинарник:
Common Public License 1.0 и IBM Public License 1.0 считаются несовместимыми с
GNU GPL. Текущая реализация не линкуется с Sleuth Kit: самостоятельные CLI
запускаются через `execv`, получают обычные аргументы командной строки и
возвращают текст либо байты файла. Общих библиотек, памяти и структур данных нет.

По критерию GNU GPL FAQ это сильный аргумент в пользу отдельных программ и
«mere aggregation». Поэтому лабораторную поставку можно готовить как агрегат
независимых исполняемых файлов при раздельном лицензировании каждого компонента.
Это инженерная оценка, а не юридическое заключение. Весь приведённый ниже
лицензионный checklist должен быть выполнен и проверен перед публикацией;
вопрос о необходимости и объёме юридической оценки модели агрегирования — в
том числе для бесплатного некоммерческого распространения — остаётся открытым
юридическим вопросом и решается координатором отдельно.

## Что фактически поставляется

| Компонент | Основной лицензированный код |
|---|---|
| `fls` | CPL 1.0 плюс общие модули libtsk под CPL/IPL и иными указанными лицензиями |
| `mmls` | CPL 1.0 плюс общие модули libtsk |
| `icat` | IBM Public License 1.0 плюс общие модули libtsk |

Все три — самостоятельные arm64 Mach-O. RecoveryApp не включает заголовки или
объектные файлы TSK в Swift-бинарник. Вложенный `tool-launcher` только создаёт
отдельную группу процессов и вызывает выбранный CLI через `execv`.

## Обязательства для бинарной поставки

Перед публикацией каждого ZIP необходимо:

1. Сохранить полные CPL 1.0, IBM Public License 1.0 и сводку copyright/licensing
   из исходного архива TSK рядом с бинарниками.
2. Явно указать, что гарантии и ответственность от имени upstream Contributors
   исключены, а отличающиеся условия предлагает только распространитель.
3. Указать, где разумным способом получить точный исходный код TSK 4.15.0;
   хранить проверенный архив и его SHA-256 вместе с релизом надёжнее одной
   внешней ссылки.
4. Не удалять и не менять copyright notices. Любые собственные изменения TSK
   идентифицировать отдельно и предоставлять их исходники под применимой
   лицензией. Текущие бинарники собраны ИЗ ИЗМЕНЁННОГО исходного кода:
   патч `Packaging/sleuthkit-preopened-fd.patch` затрагивает три файла
   (`tsk/img/raw.c` — чтение через `raw_open_readonly()` и явный `lseek`
   перед первым чтением; `tsk/util/file_system_utils.h` — объявление;
   `tsk/util/file_system_utils.c` — `dup()` унаследованного read-only
   дескриптора для путей `/dev/fd/N`), идентифицируется отдельно,
   прикладывается к релизу в
   `Contents/Resources/SourceArchives/` и применяется поверх чистого архива
   TSK 4.15.0; иной функциональности патч не добавляет.
5. Сохранить обязательную IBM copyright-строку в заметном месте уведомлений.
6. Не описывать весь `.app` как единое произведение исключительно под GPL:
   лицензия RecoveryApp, PhotoRec/untrunc и лицензии CLI TSK должны быть указаны
   раздельно.
7. Для коммерческой поставки отдельно оценить обязательство indemnification из
   раздела 4 CPL/IPL и патентные положения раздела 7.

## Релизное решение

- Допустимо для лабораторной сборки: отдельные CLI (с идентифицированным и
  приложенным патчем предоткрытого дескриптора), полные тексты лицензий,
  исходный архив и SHA-256, ясное разделение компонентов.
- Для бесплатного некоммерческого релиза: инженерные условия те же — финальная
  проверка всех пунктов checklist и сохранение архитектуры отдельных CLI.
  Некоммерческий характер поставки сам по себе не снимает лицензионные
  обязательства и не заменяет юридическую оценку модели агрегирования; вопрос,
  требуется ли для такой раздачи формальное заключение юриста, остаётся
  открытым юридическим вопросом, а не инженерным.
- Не одобрено автоматически для коммерческого релиза: требуется юридическое
  подтверждение модели агрегирования и раздела 4 CPL/IPL.
- Запрещённый для проекта вариант: статически или динамически линковать libtsk
  непосредственно в GPL-бинарник RecoveryApp.
