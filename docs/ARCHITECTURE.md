# Архитектура RecoveryApp

## Основной принцип

Интерфейс не запускает `untrunc` или PhotoRec напрямую. Он создаёт задание, а
отдельный исполнитель проверяет пути, права и свободное место, запускает вложенный
инструмент через отдельный runner, читает поток событий и гарантированно завершает
цепочку при отмене. Для физического диска `recoveryapp-readonly-helper` просит у
системного `authopen` только read-only файловый дескриптор; PhotoRec остаётся
обычным пользовательским процессом в отдельной сессии. Результат пишется на другой
физический накопитель.

## Слои

1. **SwiftUI App** — русские экраны, выбор файлов/томов, таблицы, фильтры, лог.
2. **Domain** — задания, состояния, измеряемый прогресс и понятные ошибки.
3. **Safety** — определение физического накопителя, запрет опасного пути результата,
   оценка свободного места, отслеживание отключения устройства.
4. **Tool Runner** — запуск вложенных бинарников, отдельная группа процессов,
   мягкая остановка с последующим принудительным завершением и проверкой потомков.
5. **Adapters** — парсеры реального вывода конкретных версий `untrunc`, PhotoRec и
   кандидата для метаданных. Неизвестные показатели не выдумываются.
6. **Telemetry (будущий этап)** — после готовности локального восстановления:
   явное согласие пользователя, локальная ограниченная очередь без содержимого
   файлов; отправка с коротким таймаутом и backoff не влияет на операции.

## Потоки данных

- Видео: повреждённый файл + исправный пример + отдельная папка → копия результата.
- Удалённые файлы: read-only устройство/образ → каталог находок/сигнатур → выбор →
  восстановление на другой физический диск. Предпросмотр извлекается во временную
  папку macOS.
- Лог: технические строки хранятся локально в рамках задания и не входят в
  телеметрию.

## Этапы разработки

1. Минимальная SwiftUI-основа, тесты, `.app`, ZIP и SHA-256.
2. Встроенный `untrunc`: синтетические ролики, успех/ошибка/отмена, проверка GUI —
   выполнено для arm64 и тестового H.264/AAC MP4.
3. Лабораторный стенд FAT32/exFAT: образы, удаление тестовых файлов, сравнение
   PhotoRec и инструментов метаданных, SHA-256, скорость, отмена и процессы —
   выполнено на синтетических образах; выбран порядок `fls`/`icat` → PhotoRec.
4. Интерфейс накопителей: автоматическое обнаружение, выбор результата, raw-helper,
   PhotoRec и быстрый метаданный режим FAT32/exFAT через авторизованный read-only
   дескриптор — реализовано; проверка этого режима на физическом носителе ожидается.
5. Проверки на выделенных физических носителях без личных данных.
6. Телеметрия, сеть и защищённая панель после готовности остальных функций и
   отдельного согласования схемы, домена, VPS и пользовательского согласия.
7. Лицензии, подпись, нотариализация, DMG/ZIP и оценка Intel.

## Решения, которые намеренно отложены

- Инструмент метаданных не выбран до измерений на FAT32 и exFAT.
- APFS и сохранение исходных имён/путей не заявляются без подтверждённых тестов.
- Процент и ETA появятся только там, где выбранная версия инструмента выдаёт
  достаточно данных для честного расчёта.
- Конечная лицензия приложения и схема распространения GPL-инструментов будут
  утверждены после аудита точных версий и способа связывания/поставки.
