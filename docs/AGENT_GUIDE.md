## Как выбрать проверки

Точный обязательный набор задаёт task-файл; таблица помогает оценить регресс.

| Изменение | Основные проверки |
|---|---|
| Модель, фильтр, парсер, состояние GUI | `Scripts/test.sh`; при UI — новая `.app` и визуальная приёмка |
| Аргументы/JSON CLI | `test-cli.sh` и сценарий соответствующей команды |
| Quick для образа | `test-quick-image-cli.sh`, `test-deleted-recovery.sh` |
| Физический quick/helper/FD | `test-physical-quick-cli-contract.sh`, `test-metadata-helper.sh`, `test-sleuthkit-preopened-fd.sh` — синтетика |
| PhotoRec | `test-deep-photorec-cli.sh`, `test-photorec-jpeg.sh`, `test-readonly-helper.sh` |
| Видео/носитель результата | `test-video-cli.sh`, `test-video-repair.sh` |
| Процессы и отмена | `test-cancellation.sh` и отмена в соответствующем CLI-сценарии |
| Упаковка/лицензионные файлы | `test-source-package.sh`, `test-license-package.sh` на новой `.app`, подпись |
| Инструменты/рецепты/evidence | `test-toolchain-provenance.sh --selftest`, проверка FFmpeg config, затронутый интеграционный набор |
| Только документация | Сверка с кодом, существование путей/ссылок, `git diff --check`; без заявлений о повторном runtime-тесте |

Имена в таблице без префикса тоже лежат в `Scripts/`. Зависимости и команды —
[DEVELOPMENT.md](DEVELOPMENT.md). Интеграционные тесты создают образы/кэши;
синтетические video-тесты могут подключать и форматировать собственный RAM-диск.
Это не разрешение использовать пользовательскую флешку.

## Неприкосновенные ограничения

- Реальные устройства только по прямому заданию и разрешению; перед тестом заново
  определить имя, id, raw-путь, размер, ФС и mount point. `diskN` меняется.
- Только чтение источника, результат на другом физическом диске. Не ослаблять
  authopen, проверку O_RDONLY, размера и назначения. Никакого пароля в CLI.
- Если владелец не у ноутбука и запретил запросы пароля, не запускать physical
  recovery/authopen; оставшиеся сценарии честно пометить непроверенными.
- Не открывать содержимое пользовательских результатов; сохранять чужие файлы,
  старые dist и исходные архивы. Убирать только свои точно установленные временные
  данные, не `work/` целиком без проверки принадлежности.
- Без ETA, сети/телеметрии, смены иконки, зависимостей или версии вне задания.
  Будущий сетевой этап не удалять из планов.
- При отказе защиты записать точный отказ и остановить блокируемое действие.
  Не применять `--no-verify`, не менять gate/allowlist ради коммита без решения
  владельца. Известные findings dmgbuild не означают, что они устранены.

## Завершение и передача

В `reports/TASK-NNN.md`: реализованное, изменённые файлы, точные команды и коды
выхода, evidence, непроверенное, риски, уборка. Отдельно различать свои проверки
и сведения исполнителя. Сборка не доказывает GUI и реальный authopen.

Stage только явный список файлов; проверить staged diff и
`git diff --check БАЗА..HEAD` плюс текущий staged diff. Исправления ревью — новыми
коммитами, без amend/rebase. Не ставить DONE и не сливать ветку исполнителю.
Хеш своего коммита не помещается внутрь этого же коммита: передать его отдельно.

Короткий ответ исполнителя: ветка, полный хеш последнего коммита, путь отчёта,
статус REVIEW или точный блокер. Затем остановиться. Координатор читает отчёт
и diff, повторяет рискованные проверки, выдаёт замечания файлом либо принимает.
