# Правила работы над RecoveryApp

## Роли и Git-процесс

- Codex — координатор и ревьюер. Он создаёт задания, проверяет коммиты, тесты,
  безопасность, CLI и при необходимости GUI.
- GLM — исполнитель. Он работает только по текущему файлу `tasks/TASK-NNN.md`.
- Для каждой задачи используется отдельная ветка `glm/task-NNN-краткое-имя`.
- GLM не работает напрямую в `main`, не переписывает историю и не объединяет
  ветки.
- В конце задачи GLM создаёт `reports/TASK-NNN.md`, делает итоговый коммит и
  сообщает Codex полный хеш коммита.
- Только Codex переводит задачу из `REVIEW` в `DONE` и принимает решение о
  слиянии.
- Не начинать следующую задачу без нового задания координатора.

## Обязательные документы

Перед работой полностью прочитать `PRODUCT.md`, `ARCHITECTURE.md`, `TASKS.md`,
`DECISIONS.md` и текущий файл в `tasks/`.

## Безопасность данных

- Никогда не форматировать, не стирать, не ремонтировать и не размонтировать
  пользовательский накопитель без отдельного прямого разрешения пользователя.
- Физический источник открывать только для чтения. Нельзя ослаблять `authopen`,
  native helper, проверку режима дескриптора и повторную проверку размера.
- Результат сохранять только на другой физический диск.
- Перед реальным тестом заново определить имя, `/dev/diskN`, `/dev/rdiskN`,
  размер, файловую систему и точку монтирования. Нельзя запоминать `diskN` между
  подключениями.
- Не просматривать и не публиковать содержимое восстановленных пользовательских
  файлов.
- Реальные накопители не использовать, если это прямо не требуется текущим
  заданием. По умолчанию работать с синтетическими образами.

## Границы продукта

- Интерфейс русский и рассчитан на обычного пользователя.
- Нельзя обещать точный ETA без достоверного источника данных.
- Сеть и телеметрия отсутствуют, но запланированы на отдельный будущий этап с
  явным согласием пользователя. В текущих задачах их не добавлять и не удалять
  этот план.
- Не менять иконку без нового запроса пользователя.
- Sleuth Kit остаётся отдельными CLI-процессами. Не линковать его с GPL-кодом
  RecoveryApp без отдельной юридической оценки.
- Пока нет Developer ID и нотариализации. Нельзя советовать отключать Gatekeeper.
- CLI и GUI должны использовать один `RecoveryCore`; нельзя создавать две
  независимые реализации восстановления.

## Требования к изменениям

- Делать только изменения, перечисленные в текущем задании.
- Сохранять существующую архитектуру безопасности и пользовательские файлы.
- Не считать компиляцию доказательством корректности поведения.
- Изменения UI обязательно проверять в собранной `.app` через GUI.
- Не повышать версию и build без явного пункта задания.
- Не удалять старые релизные или пользовательские файлы.
- Не добавлять внешние зависимости без решения в `DECISIONS.md` и одобрения
  координатора.

## Отчёт GLM

`reports/TASK-NNN.md` должен содержать полный хеш итогового коммита, список
изменённых файлов, реализованное, точные команды проверок и результаты, всё
непроверенное, риски и сведения об уборке временных данных.
