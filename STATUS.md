# Текущее состояние

Дата обновления: 2026-09-24

> Оперативная точка продолжения версии 0.8.1 (13) зафиксирована в
> `ARCHITECTURE.md` и `TASKS.md`. Sleuth Kit пересобран из чистого архива с
> патчем унаследованного FD и проверен на синтетических образах. Короткая
> физическая приёмка Flashka подтвердила чтение exFAT через `/dev/fd/0` и
> один системный запрос, но не полный поиск. Отдельный полный тест на 2‑ГБ
> FAT32-носителе завершил поиск и извлечение. Ниже также сохранена
> история предыдущих проверок; она не означает, что новый DMG уже прошёл
> финальный приёмочный тест.

## Реализовано

- Swift Package для нативного приложения macOS 14+ на SwiftUI.
- Главный экран с двумя рабочими направлениями и явными сообщениями об ограничениях.
- Экран конфиденциальности без фиктивных переключателей: приложение прямо
  сообщает, что в версии 0.8 сеть и телеметрия не используются, а возможный
  сетевой этап позже потребует отдельного согласия.
- Сценарии сборки `.app`, ad-hoc подписи, ZIP, установочного DMG и SHA-256.
- Каркас документации архитектуры и сторонних компонентов.
- Встроенный arm64 `untrunc` `v1-9d86ec9` со статическим FFmpeg 8.1.
- Экран видео с выбором исправного примера, повреждённого файла и папки результата.
- Живой подробный лог, реальное прошедшее время и честный неизвестный ETA.
- Отмена отдельной группы процессов без отправки сигналов процессу GUI.
- Защита от одинаковых входов и перезаписи существующего результата.
- Лабораторная arm64-сборка PhotoRec 7.2 и встроенные инструменты Sleuth Kit
  4.15.0 (`fls`, `icat`, `mmls`).
- Воспроизводимый стенд FAT32/exFAT для удалённых TXT, PNG и MP4.
- Безопасный генератор удалённых записей exFAT, не изменяющий исходный образ.
- Экран выбора raw/IMG/DMG-образа, метаданный поиск, таблица находок, множественный
  выбор и восстановление в отдельную папку без перезаписи существующих файлов.
- Автоматическое обнаружение разделов GPT через `mmls` и передача смещения в
  `fls`/`icat`.
- Глубокий поиск JPEG, PNG и MOV/MP4 через встроенный PhotoRec с явным
  предупреждением о потере имён и каталогов. Каждый запуск сохраняется в новую
  папку и не смешивается с предыдущими результатами.
- Основной пользовательский сценарий выбора подключённой флешки или карты памяти;
  образы IMG/RAW/DD/DMG перенесены в раскрываемый режим для специалистов.
- Автоматическое обнаружение внешних физических дисков через `diskutil` с именем,
  размером, raw-путём и кнопкой обновления.
- Быстрый метаданный поиск FAT32/exFAT на физическом диске через отдельный
  read-only helper: `mmls` находит раздел, `fls` показывает удалённые записи,
  `icat` восстанавливает выбранные файлы с сохранившимися именами.
- Узкий `recoveryapp-readonly-helper`: получает через системный `authopen` только
  read-only файловый дескриптор и запускает PhotoRec без root-прав.
- Двойной запрет результата на исходном диске: в Swift по точкам монтирования и
  повторно в native helper через `statfs`.
- Приложение сразу открывает главное меню; выбор накопителя, пояснение read-only
  режима и отдельная папка результата находятся внутри раздела удалённых файлов.
- Системное право на конкретный `/dev/rdisk…` запрашивает RecoveryApp через
  Authorization Services и передаёт `authopen -extauth` без передачи пароля.
- PhotoRec использует уже авторизованный дескриптор через `dup()`, не пытаясь
  повторно открыть raw-устройство по пути.
- Заголовок «Подробный лог» стал одной кликабельной строкой; журнал получил
  читаемую карточку и фильтрацию терминальных управляющих кодов PhotoRec.
- Авторизационная сессия RecoveryApp теперь удерживается до получения файлового
  дескриптора от `authopen`, чтобы не возникал второй системный запрос.
- Выбор папки результата блокируется на всё время активной операции.
- Вместо одинокой надписи про неизвестное время показывается живая карточка:
  текущий этап, прошедшее время, активный индикатор, реальное количество уже
  созданных медиафайлов и состояние обновления журнала. Проценты и ETA не
  выдумываются.
- Во время PhotoRec карточка читает его контрольную точку `photorec.ses` и
  показывает фактически обработанный объём относительно размера накопителя.
  Скорость появляется только при свежем изменении счётчика и скрывается, если
  показатель устарел; при отсутствии надёжных данных остаётся живой индикатор.
- Стартовый список накопителей стал настоящим выбором: продолжение заблокировано,
  пока пользователь явно не отметит диск; выбранный ID передаётся на экран
  восстановления без автоматического выбора первого устройства.
- Перед системной авторизацией список дисков обновляется, а после получения
  read-only дескриптора native helper сверяет фактический размер устройства с
  выбранным. Замена `/dev/rdiskN` приводит к безопасному отказу.
- Предупреждение перед PhotoRec показывает свободное место, если его меньше
  размера источника. Во время восстановления macOS не переводит компьютер в
  автоматический сон.
- В настройках появился раздел «О программе» с версией и явным разделением
  лицензий RecoveryApp, untrunc/PhotoRec, libjpeg-turbo и Sleuth Kit.
- Добавлена собственная спокойная сливово-лавандовая иконка RecoveryApp с
  минимальным внутренним объёмом, без внешнего свечения и стекла. Сетевой
  переключатель, который ничего не делал, удалён; интерфейс прямо сообщает, что
  сетевой обмен отключён.
- Добавлены крупные отдельные карточки результата: обычное восстановление,
  глубокий PhotoRec, остановка с доступом к уже найденным файлам и восстановление
  видео с показом готового файла в Finder.

## Известные ограничения

- Восстановление видео подтверждено только на небольшом синтетическом H.264/AAC;
  это не доказывает совместимость с камерами, HEVC, ProRes и большими файлами.
- Размерная сверка quick-результатов сверяет только размеры: она не проверяет
  целостность содержимого и не восстанавливает потерянные байты. Для части
  удалённых записей TSK не заполняет размер в длинном листинге (показывается 0);
  такой размер консервативно трактуется как неизвестный (`sizeUnknown`),
  поэтому достоверно пустой файл по `fls -l` определить нельзя. Неполные файлы
  сохраняются как есть, дозапрашивать данные неоткуда.
- Sleuth Kit и PhotoRec включены только в лабораторную сборку; перед бесплатной
  публичной поставкой требуется финальная проверка лицензионного checklist.
- Короткий read-only запуск на `/dev/rdisk4` подтверждён, но полный проход 125 ГБ
  намеренно не выполнялся из-за 71 ГБ свободного места на диске результата.
- Быстрый метаданный режим физического диска реализован для FAT32/exFAT и прошёл
  синтетический helper-тест. Прежний отказ Flashka на `/dev/fd/4`, затем
  `/dev/fd/0`, после расширенного патча `dup()` не повторился в короткой
  физической проверке: `fls` начал читать exFAT. Полный поиск и извлечение
  файлов с этой 125‑ГБ Flashka по-прежнему не проверены; отдельный полный
  тест на 2‑ГБ FAT32-носителе прошёл. 14 из 71 извлечённых объектов имеют
  нулевую длину, поэтому успех CLI не следует трактовать как гарантированное
  восстановление содержимого каждого файла.
- Ранее при остановке CLI во время одного лишь поиска текст ошибки ошибочно
  сообщал, что «уже готовые файлы сохранены». В TASK-004B общий текст отмены Core
  заменён на нейтральное «Операция остановлена.»; наличие результатов нужно
  определять по отдельному отчёту, а не обещать при одном лишь поиске.
- PhotoRec с `libjpeg` восстановил небольшие синтетические JPEG/PNG/MP4; на
  реальном носителе подтверждён полный проход и извлечение 44 объектов, но
  контрольные файлы не восстановлены побайтно из-за вероятной фрагментации.
- Инженерный аудит CPL/IPL завершён. Для некоммерческой поставки нужно сохранить
  модель отдельных CLI и выполнить checklist; при переходе к коммерческой модели
  потребуется отдельно оценить aggregation и indemnification.
- Панель, сеть и необязательная телеметрия отложены до готовности основных
  функций; в версии 0.8 их нет.
- Нет подписи Developer ID и нотариализации.
- Установленные Command Line Tools 27.0 содержат несовпадающие сборки компилятора
  и SDK 27.0; локально требуется явно выбрать совместимый SDK 26.5.
- Swift Testing в установленном preview Command Line Tools нестабилен из-за
  отсутствующего macro-плагина; `Scripts/test.sh` использует независимый Swift
  test harness без XCTest/макросов.
- Текущая скорость может временно скрываться между обновлениями контрольной
  точки PhotoRec или при чтении из системного кэша; устаревшее значение намеренно
  не выдаётся за текущую скорость.

## Следующий этап

RecoveryCore и быстрый режим (образ и физический накопитель) доступны CLI и
GUI. По `TASKS.md` дальше — приёмочная проверка физического `quick scan
--drive` Codex на реальном носителе с явного разрешения пользователя, затем
CLI PhotoRec, прогресс и остановка.
Для публичной поставки потребуются Developer ID, hardened runtime,
нотариализация и финальная проверка лицензионного checklist Sleuth Kit.
