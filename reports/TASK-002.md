## Доказательство прохождения именно `/dev/fd/N`

1. Маркер патча: в чистом архиве 4.15.0 подстрока `dev/fd` не встречается ни
   разу (`tar -xzf … -O | grep -c dev/fd` → `0`), а в каждом пересобранном
   бинарнике строка `/dev/fd/` есть — она существует только в коде ветки
   `dup()` из патча.
2. Функциональный FD-путь: `fls` и `icat` читают синтетическую FAT32 через
   заранее открытый унаследованный дескриптор `/dev/fd/9` и через `/dev/fd/0`
   после переноса на stdin (тот же механизм, что в
   `recoveryapp-metadata-helper`); `mmls`, `fls`, `icat` читают GPT/exFAT через
   тот же дескриптор, включая повторное использование после `mmls` (это
   покрывает явный `lseek` из патча при общем смещении продублированного
   дескриптора); `icat` даёт побайтное совпадение с эталоном.
3. Дискриминатор `dup()`: на этой macOS `open("/dev/fd/N")` переоткрывает цель
   с проверкой прав. После `chmod 000` синтетического образа обычный путь даёт
   `Permission denied`, а `dup()` заранее открытого дескриптора продолжает
   читать образ — именно этот механизм отказа наблюдался на реальной Flashka.
4. Негативный контроль: на отдельной сборке Sleuth Kit без патча тест падает с
   `FAIL: fls собран без поддержки унаследованного FD` (код 1) — запуск
   `SLEUTHKIT_TOOLS_DIR=…/sleuthkit-nopatch/bin ./Scripts/test-sleuthkit-preopened-fd.sh`;
   на пересобранной версии все проверки проходят. Дополнительно во время
   разработки тест зафиксировал отказ `raw_open: file "/dev/fd/9" - Permission
   denied` на сборке, где патч покрывал только `raw.c`, но не определение
   размера — это и привело к расширению патча.

## Почему синтетическая проверка не доказывает физический `authopen`

- На синтетике дескриптор указывает на обычный файл: `/dev/fd/N` воспроизводит
  только переоткрытие с проверкой прав. Для реального `/dev/rdiskN` путь через
  `/dev/fd/N` проходит через devfs и драйвер дискового устройства, где работает
  авторизация macOS — это поведение на регулярных файлах невоспроизводимо.
- Не проверялись сам `authopen -extauth`, диалог Authorization Services,
  передача дескриптора от helper к инструментам на настоящем устройстве и
  защита от подмены `/dev/rdiskN` между подключениями.
- Быстрый режим физического диска остаётся непроверенным на реальном носителе;
  физическая проверка — отдельная задача с явным разрешением пользователя.
