# REPORT TASK-008

## Коммит

Полный хеш итогового коммита сообщается Codex в ответе исполнителя: отчёт входит
в сам итоговый коммит, поэтому хеш коммита невозможно записать внутри него.
Ветка: `glm/task-008-regression-package`, базовый коммит
`7ce88f8a33cbdff763ba9ad4c05c46e3c22ced5b` (совпадает с `main` на момент старта).

## Исправленные дефекты (воспроизведены, в пределах задания)

1. **`icat` без явного типа ФС** (`Sources/RecoveryCore/ImageQuickRecovery.swift`).
   Воспроизведение: mformat FAT32 32 МиБ (без таблицы разделов), удалённый
   файл; GUI-восстановление → карточка «Инструмент не смог завершить
   работу»; `icat -r образ inode` вручную — код 1 «Cannot determine file
   system type». Причина: тип ФС, определённый `fls -f fat32` при скане, не
   передавался в `icat`. Исправление: `recoverBlocking` передаёт
   `-f <filesystemType>` (и `-o offset`, как раньше). После исправления GUI-
   и CLI-восстановление малого образа работает побайтно. Регрессионный
   случай добавлен в `Scripts/test-quick-image-cli.sh` (малый 32 МиБ образ).
2. **`package-source.sh` ссылался на несуществующий каталог `GLM`**
   (`Scripts/package-source.sh`) — `ditto` падал, ZIP исходников не
   собирался. `GLM` убран из списка копирования; ZIP собирается.

## Риски

- Лабораторный статус: отсутствуют Developer ID, hardened runtime,
  нотариализация — на других Mac первый запуск требует ручного
  подтверждения; автоматические тесты этого не заменяют.
- Малый FAT32-образ вскрыл слабость автоопределения TSK: образы иных
  размеров/разбивок могут вести себя иначе; после фикса тип ФС передаётся
  явно, что снижает риск.
- GUI-прогон выполнялся с переменными окружения `RECOVERYAPP_TEST_*` и
  путями инструментов — производственная сборка использует встроенные
  Tools из `.app`; поведение в GUI идентично (тот же Core).
- Лог-панель не прокручивается в маленьком окне (заметено при проверке) —
  косметика, вне TASK-008.
