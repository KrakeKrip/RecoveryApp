## Цель и найденные разрывы

CLI-first backend для quick, deep и видео уже находится в `RecoveryCore`.
TASK-007 не переписывает его заново: доведи GUI до использования тех же
правил и достоверных результатов, сохранив русский интерфейс для обычного
человека.

Сейчас `DeletedFilesViewModel` вручную повторяет сверку `diskN`/имени/размера
в трёх действиях. `DeletedFilesExecutor` создаёт новый
`PhysicalQuickRecovery` для `recover` после `scan`, теряя авторизационную
сессию. GUI quick вызывает обёртку `recover() -> [URL]` и показывает
«Восстановление завершено» без статусов `incomplete`, `sizeMismatch` и
`sizeUnknown`, хотя Core и CLI уже возвращают их через `recoverDetailed()`.
GUI deep вручную повторяет preflight папки вместо общего метода Core.

## Объём работ

1. Для физического GUI-источника перед **каждым** `scan`, `recoverSelected`
   и `deepRecover` заново получай снимок через `ExternalDriveDiscovery` и
   сверяй выбранные `diskN`, точное имя и размер через
   `PhysicalDriveSelector.selectDrive`. Не оставляй рядом ручную копию
   правил сверки. При исчезновении/подмене диска откажи до авторизации,
   оставь понятную карточку ошибки и не используй старую сессию.
2. Для физического `recoverSelected` и `deepRecover` выполняй
   `PhysicalQuickRecovery.preflightRecoveryOutput` **до** создания новой
   авторизации и запуска инструмента. Core/helper продолжают свою повторную
   проверку как второй барьер. Выбор папки во время операции остаётся
   заблокированным; папка на источнике не принимается и через symlink.
3. В GUI быстрый `scan` → `recoverSelected` по тому же подтверждённому
   физическому накопителю должен переиспользовать один экземпляр
   `PhysicalQuickRecovery` и его авторизационную сессию, а не создавать
   второй экземпляр перед `icat`. Перед восстановлением всё равно повторно
   обнаружь и сверь диск; переиспользуй сессию только при идентичности
   выбранного источника. После удачного `scan` сохрани сессию до
   `recoverSelected`; при смене источника, отмене, ошибке или завершении
   извлечения сбрасывай её безопасно. Не меняй `authopen`, helper,
   проверку `O_RDONLY`/размера и запрет записи на источник.
4. Быстрое извлечение в GUI переведи на `recoverDetailed()` Core (и для
   образа, и для физического источника). Сохраняй `RecoveredFileResult`/
   агрегаты статусов, а не только `[URL]`. В карточке результата показывай
   сколько файлов сохранено и сколько имеют `incomplete`/`sizeMismatch`/
   `sizeUnknown`; проблемные файлы **не удаляются** и папка открывается как
   раньше. Если есть неполные/несовпадающие, не показывай безоговорочно
   зелёную карточку «Восстановление завершено»: нужны спокойный
   предупреждающий заголовок и понятное пояснение. Неизвестный размер
   также нельзя представлять как доказанную полноту. Совпадение размеров
   не называй проверкой целостности содержимого. Пустой quick-результат
   должен иметь нормальное состояние без ложной ошибки/успеха «сохранено 0».
5. Остальные направления оставить на общем Core: GUI PhotoRec делегирует
   `PhotoRecDeepRecovery`, видео — `VideoRepairExecutor` из Core. Можно
   упростить тонкий GUI-адаптер, но не переносить в SwiftUI алгоритмы
   процессов, parsing, прогресса или выбора имени результата. UI-специфичное
   форматирование текста и анимации могут остаться в ViewModel.
6. Сохрани текущие карточки успеха/отмены/ошибки, Finder-кнопки, выбор
   диска/образа/папки, русский текст, реальный прогресс без обещанного ETA,
   режим без автоматического сна и доступность подробного лога. Не меняй
   иконку, версию/build, CLI-контракты, сеть, телеметрию, обновления или
   упаковку. Существующие source-only права не ослаблять.
7. Обнови `ARCHITECTURE.md`, `STATUS.md` и при необходимости `README.md`
   только фактическими изменениями GUI/Core. Не объявляй физическую
   приёмку пройденной на основании синтетики.

## Проверки и критерии приёмки

- Доменно проверь повторную сверку `PhysicalDriveSelector`: тот же источник,
  исчезнувший `diskN`, другое имя, другой размер; в трёх случаях отказа
  авторизация не создаётся. Проверь preflight папки до авторизации, включая
  путь через symlink к точке монтирования источника. Для тестируемости
  можно ввести узкий dependency-injection seam, но production GUI обязан
  использовать реальные Core/Discovery/Authorization и не допускать обхода
  политики через переменную окружения.
- Проверь жизненный цикл одной физической quick-сессии на синтетическом
  backend/shim: `scan` и `recoverSelected` переиспользуют её при неизменном
  диске; смена диска/отмена/ошибка сбрасывают. **Не** вызывать реальный
  `authopen` и не запрашивать пароль в этой задаче. Фактическое число
  системных диалогов остаётся неподтверждённым до отдельной физической
  приёмки — честно укажи это в отчёте.
- Добавь доменные проверки сводки `RecoveredFileResult` для всех статусов:
  пустой набор, все `sizeMatches`, `incomplete`, `sizeMismatch`,
  `sizeUnknown`. Убедись, что число сохранённых файлов не уменьшается из-за
  статуса и текст предупреждения не утверждает побайтную целостность.
- Выполни `./Scripts/test.sh`, `./Scripts/test-cli.sh`,
  `./Scripts/test-quick-image-cli.sh`, `./Scripts/test-physical-quick-cli-contract.sh`,
  `./Scripts/test-deep-photorec-cli.sh` и `./Scripts/test-deleted-recovery.sh`.
  Для GUI используй небольшой синтетический FAT32/exFAT-образ, не личные
  файлы и не подключённый физический накопитель. Не создавай большие образы
  только ради этой задачи.
- Собери release `.app` в **отдельную временную папку**, не перезаписывая
  `dist/RecoveryApp.app`; проверь `codesign --verify --deep --strict`.
  Обязательно запусти именно эту сборку через GUI и визуально проверь
  изменённую quick-карточку: полный и неполный/неизвестный результат,
  кнопку «Открыть папку», а также ошибку смены источника/папки на источнике
  (для недоступного физического сценария — безопасная GUI-имитация).
  Проверь, что прежние экраны deep PhotoRec и видео визуально открываются
  без регресса. В отчёте укажи точный bundle path, версию/build,
  наблюдаемые тексты, что проверено реально через GUI, а что только
  имитацией. Одной компиляции недостаточно.
- `git diff --check` от базового коммита; итоговое дерево чистое, кроме
  заранее известной нетрекаемой пользовательской папки результатов.
