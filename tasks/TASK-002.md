# TASK-002 — Sleuth Kit и унаследованный read-only дескриптор

## Статус и ветка

- Статус: `TODO`.
- Ветка: `glm/task-002-sleuthkit-fd`.

## Цель

Перед добавлением быстрого восстановления в CLI получить воспроизводимую
сборку `mmls`, `fls` и `icat`, которая читает уже открытый read-only файловый
дескриптор через `/dev/fd/N`, не пытаясь повторно открыть исходный путь.

Это подготовительная задача. Она не должна запускать восстановление с
физического накопителя и не должна добавлять новые команды CLI.

## Исходное состояние

- На реальной `Flashka` старая сборка завершалась ошибкой
  `raw_open: file "/dev/fd/4" - Permission denied`, затем аналогично для
  `/dev/fd/0`.
- `recoveryapp-metadata-helper` уже проверяет размер и `O_RDONLY`, переносит
  полученный дескриптор на stdin и передаёт `/dev/fd/0`.
- Текущий `Packaging/sleuthkit-preopened-fd.patch` использует прямой `dup()` в
  `tsk/img/raw.c`, но эта последняя версия патча ещё не была независимо
  пересобрана и проверена.
- Текущие бинарники нельзя считать доказательством того, что именно последняя
  версия патча попала в сборку.

## Обязательные изменения

1. Из чистого архива `outputs/sleuthkit-4.15.0-source.tar.gz` пересобрать
   arm64-бинарники командой `Scripts/build-sleuthkit.sh` с текущим патчем.
2. Убедиться, что патч применяется к чистому исходнику один раз и сборка не
   использует старое дерево или старые объектные файлы.
3. Проверить и при необходимости минимально исправить
   `Packaging/sleuthkit-preopened-fd.patch`, чтобы для корректного пути
   `/dev/fd/N` Sleuth Kit делал `dup()` существующего дескриптора, а обычные
   пути продолжал открывать через `open(..., O_RDONLY ...)`.
4. Не ослаблять проверки `recoveryapp-metadata-helper`: источник остаётся
   `O_RDONLY`, размер обязан совпадать, назначение `icat` не может находиться на
   исходном физическом устройстве.
5. Добавить отдельный детерминированный сценарий
   `Scripts/test-sleuthkit-preopened-fd.sh`. Он должен на небольших
   синтетических файлах без sudo и без физического диска доказать как минимум:
   - `fls` читает FAT32 через заранее открытый read-only FD;
   - `mmls` читает GPT/exFAT через заранее открытый read-only FD;
   - `icat` извлекает контрольный файл через заранее открытый read-only FD;
   - извлечённый файл побайтно совпадает с эталоном;
   - обычный путь к образу по-прежнему работает;
   - недопустимый `/dev/fd/...` завершается ненулевым кодом без падения.
6. Тест обязан обращаться к `/dev/fd/N` напрямую или через
   `recoveryapp-metadata-helper` после `dup2` на stdin. Простая проверка образа
   по его обычному пути не считается регрессией унаследованного FD.
7. Обновить `STATUS.md` только фактическими результатами этой задачи. Явно
   написать, что синтетический FD-тест не доказывает работу `authopen` на
   физическом накопителе.
8. Обновить SHA-256 встроенных `fls`, `icat`, `mmls` в отчёте. Не менять версии
   компонентов.
