## Общий сервис

Новый публичный сервис/модели RecoveryCore, не зависящие от SwiftUI, применимые позже из GUI. Проверка одного локального файла за вызов, не обход папки и не batch. Возвращать типизированный результат: абсолютный путь, schemaVersion 1, detectedFormat, status, стабильный reasonCode, короткое русское message, checksPerformed (машинные имена реально выполненных проверок), limitations (всегда непустой массив). Не выводить EXIF, содержимое, пользовательские теги или сырой системный текст в обычный отчёт. Размерная сверка RecoveredFileResult остаётся отдельной и не меняется.

Статусы:
- `imageDecoded`: «Изображение удалось прочитать». Только реально декодированный JPEG/PNG. Пояснение: «Это не подтверждает совпадение с исходным фото или полноту восстановления».
- `containerReadable`: «Структуру видео удалось прочитать». Только выполненные ниже проверки MOV/MP4. Всегда пояснять: «Кадры и звук не проверялись; видео может быть повреждено».
- `possibleDamage`: «Обнаружены признаки повреждения» — конкретный воспроизводимый структурный/декодирующий дефект поддерживаемого формата или пустой файл.
- `notChecked`: «Файл не проверен» — неизвестный формат, неподдерживаемый вариант/кодек или ресурсный предел. Не путать отсутствие поддержки с повреждением.

Не использовать «Файл исправен», «100% восстановлен», «Целостность подтверждена».

## Preflight и безопасность

Только локальный обычный читаемый файл. Каталоги, FIFO/socket/devices и symlink отвергать с понятной типизированной ошибкой, без чтения special files. Проверить тип открытого файлового дескриптора fstat, открыть O_RDONLY; не ограничиваться расширением или exists до open. Определять формат ограниченным чтением сигнатуры; расширение — подсказка, не доказательство. Вход с неподдерживаемой сигнатурой даже под .jpg не выдавать за успешную проверку. Файл с нулевой длиной — possibleDamage/emptyFile. Исчезновение, отказ доступа и изменение идентичности/размера файла между началом/концом — ошибки выполнения (никакого успешного stale-отчёта). Не создавать sidecar и не менять права/времена файлов намеренно.

Проверка запускается только явно пользователем через CLI. Тесты — только подготовленные синтетические данные; пользовательские outputs не читать и не хешировать. Не выполнять любые приложения/скрипты по содержимому файла.

## JPEG/PNG

Системные ImageIO/CoreGraphics; проверить распознавание фактического типа, размеры и успешное декодирование пикселей (чтение свойств/thumbnail/создание ленивого объекта само по себе не достаточное доказательство декодирования). Только одиночные JPEG/PNG; анимацию/APNG и прочие неподдерживаемые варианты честно помечать notChecked, если реализация не проверяет все данные. Статусы/предупреждения ImageIO должны учитываться: усечённый поддерживаемый файл не маркировать imageDecoded только потому, что библиотека смогла нарисовать часть.

Ресурсные пределы до полного декодирования: файл максимум 64 000 000 байт и максимум 40 000 000 пикселей. Арифметика размеров checked, включая width*height/rowBytes. Превышение — notChecked/resourceLimit, не авария или possibleDamage. Не читать весь произвольный файл в Data до проверки размера. Не обещать, что эти пределы гарантируют безопасную обработку любых враждебных медиа; задокументировать ограничения.

## MOV/MP4: только контейнер

На первом этапе локальный ограниченный разбор ISO BMFF/QuickTime boxes через read-only файл, без AVPlayer/AVAsset загрузки внешних ресурсов, без ffprobe/нового CLI или декодера. Стриминговое чтение заголовков/необходимых метаданных; большие mdat пропускать по размеру, не загружать в память.

Проверить допустимые размеры и границы boxes (обычный/extended size, size=0 до конца родителя), checked offsets, отсутствие обрезанных заголовков/выхода за родителя/зависания на нулевом шаге; целый moov, наличие mdat и хотя бы одного корректно размещённого video trak с mdia/hdlr типа vide. Не достаточно поиска строки moov в сырых байтах. Неизвестные boxes разрешены и пропускаются безопасно. Fragmented/container variants, которые этот ограниченный checker не умеет подтвердить, — notChecked/unsupportedVariant, не ложный containerReadable.

Ограничить глубину 16, число посещённых boxes 100 000, суммарно прочитанные метаданные 16 000 000 байт; ресурсный предел — notChecked. Покрыть проверками граничные размеры/overflow. Успех утверждает только эти структурные проверки; корректный контейнер с испорченным mdat может получить containerReadable с обязательным предупреждением о непроверенных кадрах/звуке. Этот сценарий включить в тесты как подтверждение ограничений. Не объявлять полную проверку sample tables/медиа выполненной, если её нет.

## CLI

`recoveryapp-cli verify --file FILE [--json]`

Без изменения существующих quick/deep/video contracts. Строгий разбор: missing value (включая известную опцию вместо значения), неизвестные/дублирующиеся параметры, лишние позиционные аргументы — код 2. `--file` обязательно, raw drive/output/reference/image опции здесь не принимаются. Текст и help по-русски; JSON — один валидный объект stdout, диагностика stderr.

Коды: 0 — проверка закончилась и есть отчёт, в том числе possibleDamage/notChecked; 1 — ошибка выполнения/preflight; 2 — usage. Это явно зафиксировать в help/документации/тестах, чтобы code 0 не трактовался как исправность файла. Проценты/ETA не добавлять. В CLI ошибка — stderr, без частичного JSON-отчёта в stdout.
