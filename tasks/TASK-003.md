## Цель

Перенести быстрый поиск удалённых записей в общий `RecoveryCore` и дать ему
детерминированный CLI-интерфейс для обычных файлов-образов. Поддержать поиск и
восстановление через `mmls`, `fls`, `icat` без GUI, без системного разрешения и
без физического накопителя.

Физический `/dev/rdiskN`, `authopen` и `recoveryapp-metadata-helper` относятся
к TASK-004 и в этой задаче не используются.

## Команды CLI

```text
recoveryapp-cli quick scan --image IMAGE [--json]
recoveryapp-cli quick recover --image IMAGE --output DIRECTORY --all [--json]
```

- `scan` ничего не записывает и возвращает найденные удалённые файлы.
- `recover --all` повторно сканирует образ и восстанавливает все найденные
  записи в указанную папку.
- Обычный вывод — русский. JSON идёт только в stdout; диагностика — в stderr.
- Успех — код 0, ошибка выполнения — 1, ошибка аргументов — 2.

## JSON-контракт

Минимальная схема результата поиска:

```json
{
  "schemaVersion": 1,
  "source": "/absolute/image.img",
  "candidates": [
    {
      "inode": "37",
      "path": "RECOVERY.TXT",
      "displayName": "RECOVERY.TXT",
      "partitionOffset": 0,
      "filesystemType": "fat32"
    }
  ]
}
```

Минимальная схема восстановления:

```json
{
  "schemaVersion": 1,
  "outputDirectory": "/absolute/result",
  "recoveredCount": 1,
  "files": ["/absolute/result/RECOVERY.TXT"]
}
```

Пустой массив кандидатов допустим. Порядок ключей не является контрактом.

## Обязательные изменения

1. Вынести из `RecoveryApp` в `RecoveryCore` общие части быстрого режима для
   файлов-образов:
   - модель кандидата;
   - парсинг `mmls`/`fls`;
   - поиск FAT32/exFAT, включая GPT offset;
   - восстановление через `icat`;
   - безопасное уникальное имя результата и удаление `.partial` при ошибке;
   - типизированные ошибки, необходимые CLI и GUI.
2. Сделать API `RecoveryCore` независимым от SwiftUI/AppKit и пригодным для
   dependency injection путей `mmls`, `fls`, `icat`.
3. GUI должен продолжить использовать ту же общую реализацию для образов.
   Нельзя оставлять две копии парсера или алгоритма image scan/recover.
4. Не переносить в Core и не менять физический путь с Authorization Services,
   `authopen` и metadata helper — это следующий пакет.
5. Расширить тестируемый разбор CLI-аргументов указанными командами. Обязательные
   параметры должны проверяться; неизвестные и конфликтующие параметры должны
   завершаться кодом 2.
6. Для CLI разрешать пути инструментов через существующие переменные окружения
   `RECOVERYAPP_MMLS_PATH`, `RECOVERYAPP_FLS_PATH`, `RECOVERYAPP_ICAT_PATH`.
   Добавлять внешние зависимости нельзя.
7. Проверять до запуска:
   - образ существует и является обычным файлом;
   - output существует, является каталогом и доступен для записи;
   - `--output` не является самим файлом образа;
   - все три инструмента существуют и исполняемы.
8. Не перезаписывать существующие результаты. При одинаковом имени выбирать
   новое безопасное имя существующим правилом проекта.
9. Имена из `fls` не должны позволять выход за пределы output через `..`, `/`,
   обратный слеш или абсолютный путь. В результирующей папке используется
   безопасное имя файла.
10. Добавить `Scripts/test-quick-image-cli.sh` с полностью синтетическими
    FAT32 и GPT/exFAT сценариями. Проверить поиск, JSON, восстановление, точное
    содержимое, повторный запуск без перезаписи и ошибочные аргументы.
11. Дополнить доменный harness тестами нормализации опасных имён и парсера CLI.
12. Обновить справку CLI и `STATUS.md` только подтверждёнными фактами.
