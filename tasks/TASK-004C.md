## Основание

На физической USB-флешке FAT32 размером 2055208960 байт CLI нашёл 71 удалённую
запись и завершил восстановление кодом 0. Проверка `fls -l` показала, что 14
записей имеют исходный размер 0 байт. Сравнение размеров по множеству значений
выявило также три несоответствия: размеры 4246, 65536 и 78976 байт в метаданных
против трёх результатов по 4096 байт. Имена и содержимое этих файлов не
просматривались. Код 0 от `icat` не гарантирует полноту результата.

## Цель

Показывать CLI, какие файлы совпали с ожидаемым размером, какие извлечены не
полностью, какие имеют неожиданно больший размер и где исходный размер
неизвестен. Нулевой исходный размер считать отдельным нормальным состоянием,
а не ошибкой восстановления.

Размерное совпадение не является побайтной проверкой и не должно называться
проверенной целостностью: метаданные файловой системы могут быть неполными или
повреждёнными.

## Архитектура

1. Добавить к `DeletedFileCandidate` необязательный `expectedSize: Int64?`.
   Сохранить совместимость существующих инициализаторов/фикстур, где размер
   отсутствует.
2. Получать ожидаемый размер из `fls -l` для образного и физического quick
   режима. Физический `recoveryapp-metadata-helper` может лишь добавить `-l`
   к существующему запуску `fls`; не менять authopen, O_RDONLY, проверку размера
   устройства, output-on-source или схему передачи FD. Sleuth Kit по-прежнему
   запускается отдельным CLI-процессом.
3. Обновить парсер так, чтобы он отделял исходный путь от дополнительных
   колонок `fls -l`, извлекал размер и сохранял прежние inode, путь, смещение,
   файловую систему и фильтрацию каталогов. Не путать табуляции в формате
   вывода с именем файла.
4. В общем `RecoveryCore` сформировать результат для каждого успешно созданного
   файла: URL, expectedSize, actualSize и статус:
   - `expectedEmpty`: expectedSize и actualSize равны нулю;
   - `sizeMatches`: известный положительный expectedSize равен actualSize;
   - `incomplete`: actualSize меньше expectedSize;
   - `sizeMismatch`: actualSize больше expectedSize;
   - `sizeUnknown`: expectedSize отсутствует.
5. Не терять короткий результат: сохранять его в итоговой папке и помечать как
   `incomplete`. Удалять `.partial` только при ошибке/отмене до публикации
   результата. Для размеров неизвестного исходника сохранять существующее
   поведение, но явно помечать результат как `sizeUnknown`.
6. Сохранить текущие CLI JSON поля `recoveredCount` и `files`. Добавить
   машинно-читаемые статусы по файлам и агрегированные счётчики для совпавших,
   неполных, пустых, больших ожидаемого размера и неизвестного размера
   результатов. `recoveredCount` по-прежнему означает число опубликованных
   файлов. Текстовый CLI должен предупреждать о неполных/несовпадающих размерах.
7. По возможности сохранить текущий API `recover() -> [URL]` для GUI через
   тонкую обёртку над единым детальным backend. Не менять раскладку SwiftUI и не
   повышать версию/build в этой задаче.
