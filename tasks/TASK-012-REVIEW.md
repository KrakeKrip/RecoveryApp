## Дополнение пользователя: МБ вместо МиБ

Пользователь прямо запросил привычную надпись «МБ». Это дополнение имеет приоритет над прежним требованием TASK-012 использовать МиБ: перейти на десятичные мегабайты, 1 МБ = 1 000 000 байт, во всех новых фильтрах (UI, Core, тесты, документация, пользовательские ошибки). Не переименовывать МиБ в МБ без изменения арифметики. Поля «Минимум, МБ»/«Максимум, МБ», пояснение «МБ · включительно». Обновить именование нового API и безопасную границу Int64.max / 1_000_000. Описанные ниже воспроизведения сделаны на прежнем МиБ-коде: после перехода на МБ обязательно проверить новую границу + 1 отдельно. Существующие несвязанные показатели объёма/скорости не менять.

## 1. P1: переполнение МиБ → байты приводит к падению

`FindingsSizeRange.parse(minimumText: "8796093022208", maximumText: "")` возвращает success, затем `byteRange` умножает Int64 на 1_048_576 и аварийно завершается. Codex воспроизвёл на текущем RecoveryCore: процесс завершился кодом 133. Ограничить ввод безопасным максимальным порогом (Int64.max / 1_048_576) и обеспечить безопасное поведение публичного range API при непосредственном конструировании недопустимого диапазона: никакого unchecked overflow. Добавить тесты минимума и максимума: безопасная граница, граница + 1, Int.max, прямой initializer. Не подменять переполнение оборачиванием арифметики.

## 2. P2: неверный ввод снимает прежний фильтр размера

При ошибке parsedSizeRange возвращает пустой диапазон. Codex проверил на production-модели: корректный минимум 1 МиБ показывает [f2]; после ввода abc список расширяется до [f1,f2,f3,f4,f5,f6]. Это противоречит комментарию setSizeThresholds и требованию не применять ошибочный запрос. Сохранять последний валидный применённый диапазон отдельно от текста полей/ошибки. Ошибка блокирует recovery, но не снимает последний валидный диапазон. Сброс очищает применённый диапазон, тексты и ошибку. Проверить взаимодействие с типом/именем и выбором, исправление ошибки и смену источника.

## 3. P2: при единственном неверном поле кнопка сброса отключена

Codex подтвердил: категория All, пустое имя, minimum abc → isFilterActive == false. Панель использует это значение для disabled кнопки «Сбросить фильтры». Разделить наличие введённых значений/ошибки и наличие применённого фильтра или изменить доступность сброса. Пользователь должен иметь возможность сбросить неверный ввод одной кнопкой. Тест + GUI-сценарий.

## 4. P2: запрет операции существует только в кнопке

canRecover учитывает ошибку порогов, но recoverSelected не проверяет её и сразу переходит в recovering. Добавить защиту в метод операции: при ошибке, busy либо отсутствии видимого выбора не создавать task, не запускать executor и не запрашивать авторизацию. canRecover должен учитывать именно видимый выбор. Добавить тест production-модели с безопасным записывающим тестовым seam: прямой вызов recoverSelected при ошибке ничего не запускает. Не использовать реальный диск/authopen для теста.
