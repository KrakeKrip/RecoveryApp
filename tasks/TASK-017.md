# TASK-017 — находки по мере поиска и параллельное сохранение

Исполнитель Codex; пользователь прямо разрешил реализацию, main и новый пакет.
Ветка codex/task-017-live-quick-recovery. Версию/build не повышать.

- Один потоковый Core для image/physical: строки fls декодируются из байтов,
  Unicode/границы чанков/дубли; никакого ожидания полного stdout для публикации.
- stdout PTY (для line buffering fls), stdin авторизации остаётся pipe/raw FD;
  stderr отдельно и параллельно дренируется. Никакой смены TSK/CLI архитектуры.
- Поиск и сохранение используют отдельные процессы/FD/отмену. Физическая
  авторизационная сессия переиспользуется, проверки до каждого сохранения.
- UI: живой список/выбор/фильтры во время scan; новые находки не выбираются
  молча; сохранённые отмечены и не запускаются повторно; можно остановить
  только поиск или только сохранение. Уже опубликованные файлы не удаляются.
- При остановке/ошибке сохранить находки и завершённые результаты, без ложного
  полного успеха. Подмена источника, устаревшие callbacks и закрытие окна учесть.
- Синтетика: streaming до завершения fls, одновременный icat, независимая отмена,
  частичный успех при ошибке, Unicode, CLI regression, helper/FD regression.
- Свежая .app и GUI настоящими кликами; новый DMG/ZIP/source/SHA, main/Latest
  только после проверок. Старые артефакты и пользовательские данные сохранить.
- Не трогать текущую операцию пользователя, не сканировать реальный носитель,
  не вызывать authopen/пароли в приёмке. Backend остаётся read-only, без сети.

чтение физического носителя и новый режим на 14.5 не объявляются проверенными.
